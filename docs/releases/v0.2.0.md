# MIRA 0.2.0

Release date: 2026-07-15.

MIRA 0.2.0 completes the direct inference path for Qwen3-VL-Embedding and adds
a portable vector artifact lifecycle. The release keeps model loading at the
integration boundary while configuration, media trust, representation
semantics, checkpoints, mining, evaluation, and artifact verification remain
owned by MIRA.

## Direct Qwen3-VL-Embedding inference

`load_encoder` and `mira encode` now load the audited Qwen3-VL-Embedding-2B or
8B revision directly through Transformers with `trust_remote_code=False`.
Remote models, native MIRA checkpoints, and local exports share one
backend-neutral `Encoder` contract.

The runtime provides:

- strict dependency, device, dtype, model ID, and immutable revision checks;
- official prompt construction and explicit query or document methods;
- descriptor-bound media snapshots with checksum verification;
- text, image, video, and mixed-modal global embedding contracts;
- last-token pooling through the attention mask;
- optional trained MRL prefixes followed by L2 normalization;
- bounded batching and explicit rejection of silent truncation or fallback;
- native checkpoint PEFT reconstruction and checksum-verified export loading.

The real Qwen3-VL-Embedding-2B revision passed text and image inference on
Apple MPS/FP16. The 8B weight path, real PEFT injection or merge, real export
and reload, CUDA, and model quality remain `NOT RUN`.

## Encoded artifact lifecycle

`mira encode` now writes `mira.encoded.v2` directories. Safetensors shards and
row-aligned JSONL records carry per-file checksums, while the manifest binds:

- query or document role;
- normalization state, dtype, dimension, and row count;
- model, revision, source, config, backend, and template provenance;
- canonical shard ordering and exact file set.

Publication uses an atomic no-replace directory rename. The reader binds the
root directory, rejects symlinks and special files, snapshots one shard at a
time, checks global ID uniqueness and normalization, and can either stream
shards or materialize one preallocated matrix. Materialization validates every
shard before allocating, applies an 8 GiB default byte budget, then fills the
matrix through a second verified pass.

Mining and evaluation enforce query and document roles. Exact hard-negative
mining now computes query and corpus blocks without allocating the full score
matrix, while preserving dense exact ranking and corpus-order tie breaks.

## Installed framework experience

The wheel includes two reference experiment configs. A new installation can
start without a source checkout:

```bash
python -m pip install "mira-embed[inference-qwen3-vl-embedding]"
mira init-config --output mira.yaml
mira doctor --workflow inference --config mira.yaml
```

`mira migrate-encoded` converts a trusted legacy v1 tensor bundle into v2 only
after the user provides its missing role and normalization semantics.

## Naming and compatibility

Every public capability uses the complete Qwen3-VL-Embedding name. The generic
`Qwen3VLModel` string is limited to the upstream Transformers architecture
class. The internal `qwen3_vl_emb` identifier appears only at the MS-SWIFT and
v0.1 compatibility boundaries.

The release intentionally replaces ambiguous pre-1.0 public names and paths.
Follow the [v0.2 migration guide](../migration/v0.2.md) for exact mappings.
Legacy export manifests remain readable only when their historical pooling and
template labels appear as the exact known pair.
