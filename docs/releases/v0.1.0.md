# MIRA 0.1.0

Release date: 2026-07-15.

MIRA 0.1.0 packages a backend-independent CPU reference framework for
post-training multimodal embedding and retrieval models. The release keeps
record semantics, objectives, distributed loss rules, evaluation, mining,
checkpointing, and inference provenance outside any one model-training
backend.

Publication is allowed only when every required pre-tag row in the
[release ledger](../release-status.md) is `PASS`. The readiness score is the
percentage of required pre-tag gates marked `PASS`, and the threshold is
strictly greater than 99.9%. Post-publication repository, hosted CI, tag,
release, and download checks are tracked separately and do not inflate that
score.

## Included in 0.1.0

- Strict versioned configuration supports composition, interpolation,
  migration, early capability validation, and canonical checksums.
- Multi-positive multimodal JSONL records carry explicit query, positive,
  negative, media, task, and dataset semantics. Validation rejects malformed
  or escaping media paths before training.
- `GroupLayout` is the sole source of supervision for multi-positive InfoNCE,
  Matryoshka Representation Learning, false-negative masking, distributed
  gathering, and global-query loss scaling.
- Deterministic sampling and hard-negative mining preserve positive maps,
  ordered output identities, and artifact checksums.
- Exact retrieval evaluation reports Recall, Precision, Hit Rate, MRR, MAP,
  NDCG, per-query evidence, slices, and bootstrap confidence intervals without
  claiming that an evaluator implementation is a trained-model result.
- Atomic checkpoints verify their manifests, file set, checksums, provenance,
  resume mode, and complete state before restoration.
- Encoding, evaluation, mining, checkpoint, and export artifacts bind model,
  adapter, template, representation, normalization, dataset, and file
  identities where applicable.
- Nine CLI workflows cover configuration inspection, data validation,
  diagnostics, mining, exact evaluation, encoding, export, and reference
  training.
- A dependency-lazy facade defines the audited MS-SWIFT and
  Qwen3-VL-Embedding integration boundary without importing Swift into MIRA's
  core mathematical packages.

## MS-SWIFT security boundary

The source adapter is pinned to MS-SWIFT 4.4.1 at immutable commit
`98a09c18cdf95ff07051324b9b8cc90f5184b24b`. MIRA 0.1.0 does not publish an
`ms-swift` dependency extra because the compatible dependency resolution
retains known advisories in Gradio, Pillow, and Starlette. Installing the
backend manually is outside the supported release boundary and does not turn
an unexecuted lane into a pass.

The facade uses Swift entry points for model, processor, template, and trainer
construction, and it uses PEFT for LoRA construction. It sends checkpoint save
and resume through MIRA's `CheckpointManager` and export through MIRA's Qwen
adapter. MIRA does not claim compatibility with Swift-native checkpoints.

## Evidence boundary

The following lanes are `NOT RUN` for this release:

- MS-SWIFT 4.4.1 installation and a real backend import
- Qwen3-VL-Embedding-2B and 8B weight download, forward, training, export, and
  reload
- PEFT injection or merge against a real Qwen model
- CUDA, NCCL, multi-GPU, and multi-node execution
- DeepSpeed ZeRO-2 and ZeRO-3
- FlashAttention 2
- Phase-1 training-time validation
- trained-checkpoint retrieval quality and all Qwen model-quality evaluation
- accelerator latency, throughput, memory, and scaling measurements
- optional FAISS parity and performance

The CPU/Gloo two-rank verifier is evidence only for the collective and gradient
semantics it exercises. It is not evidence for a Qwen model, accelerator,
multi-node training, or production DeepSpeed support. The
[benchmark report](../benchmark-report.md) records one non-publishable
single-shot CPU diagnostic and no publishable performance or model-quality
result.

## Compatibility and licensing

Python 3.11 and 3.12 are the declared release targets; all 902 tests passed on
both interpreter lines during pre-tag verification. The base package uses
PyTorch without installing the security-blocked backend graph. MIRA, MS-SWIFT,
and the two target Qwen model repositories declare Apache License 2.0. Dataset
rights remain separate from model and code licensing; provenance records do
not grant permission to use or redistribute a dataset.
